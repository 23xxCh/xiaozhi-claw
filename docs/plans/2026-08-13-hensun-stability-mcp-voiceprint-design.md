# Hensun 夜间稳定性、MCP 搜索与声纹识别设计

## 当前边界

今晚只运行隔离的安全长稳实验：后端使用 mock provider，ESP32 只保持局域网 WSS 在线并低频探测，不刷机、不擦除 NVS、不保存原始音频或逐句文本。现有工作树中的音频和固件改动保留，夜间产物只写入被 Git 忽略的 `run/soak/`。

## 夜间长稳

长稳脚本启动独立的控制面和实时网关，使用临时 SQLite 数据库与 `PROVIDER_MODE=mock`。每轮通过固定短句和 Opus 样本执行 `listen.start → 音频 → listen.stop → stt → llm → tts → drained`，并在每轮重建 WebSocket 连接。打断、慢消费者、重复 listen 和 provider 超时由独立回归测试覆盖，不在夜间脚本中虚构为已注入场景。每小时对当前 ESP32 做一次只读在线探测，不触发麦克风、播放或设备工具。

监控只保留阶段、错误码、耗时、连接重试、音频帧计数、任务数、控制面与网关进程内存/CPU累计时间和数据库行数。8 小时后停止，生成 `run/soak/<timestamp>/report.json` 和 `report.md`。队列峰值、真机在线率和任务泄漏必须结合网关指标及真机报告验收，不能仅凭本脚本自动宣称通过；任何失败都必须保留证据。

## MCP 与工具调用

服务端增加 `ToolRegistry`，把云端工具和设备 MCP 工具统一为名称、JSON Schema、风险级别、超时和异步执行函数。首批低风险工具为当前时间、计算器、天气、联网搜索；设备工具先开放音量和亮度。重启、OTA、解绑、截图上传默认只能由明确的用户操作触发。

网关在设备 hello 声明 MCP 后发送 `initialize` 和 `tools/list`，缓存工具列表；调用时使用标准 JSON-RPC `tools/call`，设备离线、超时、未知工具和非法参数均返回稳定错误。DeepSeek Tool Calls 接通后，模型的 `tool_calls` 由服务端执行，再用 `role=tool` 回传结果，继续流式生成最终回复。开发环境可注入确定性的 `MockSearchProvider` 做协议和 UI 验证；真实搜索服务只通过后端 Secret 配置，默认关闭，不把模拟结果冒充实时网页结果。

## 声纹识别

声纹采用可替换的 `SpeakerVerificationProvider`。首版先完成接口、策略和 Mock：录入、删除、重新录入、未知身份回退成人默认档案。生产实现优先评估本地 3D-Speaker，与 ASR 并行；不保存原始音频，只保存加密特征。声纹不用于 VAD 降噪，也不作为支付、解绑或 OTA 的唯一授权。家庭模式默认关闭，正式开放前完成单独同意、影响评估和删除流程。

## 后续验收

- 后端测试、双进程和 WSS 冒烟通过。
- MCP initialize/list/call 顺序、超时、离线和越权测试通过。
- 普通对话不调用工具，搜索超时有明确降级提示。
- 声纹模板可删除，日志和数据库不含原始音频、逐句文本、密钥或令牌。
- 真机完成 10 轮语音回归后，才进入下一阶段的真实搜索和声纹灰度。

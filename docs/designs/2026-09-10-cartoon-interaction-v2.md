# Hensun 活泼卡通交互：第二阶段设计

日期：2026-09-10。状态：待实现与真机验收。本设计不代表已刷入的固件具备下列完整能力。

## 基线与目标

用户已反馈修正启动接口后的设备可以聊天；连续多轮、尾字、8 小时长稳仍未放行。当前 NOCAM 使用 320×240、10 FPS 的九套既有 GIF。托管路线明确表情请求已提交，但运行网关尚未加载该变更。保留当前角色外观、半双工交互及供应商选择，不增加模型调用，不切换语音路线。

下一阶段优先级：连续对话稳定 → 状态准确 → 情绪不被覆盖 → PCM 嘴型 → 过渡、字幕细化。若再次出现不回复，保留失败样本并先关闭阻断，不以动画上线代替稳定性修复。

## 用户可见流程

| 阶段 | 表情与动作 | 文字与退出条件 |
|---|---|---|
| 安静待机 | 既有困倦动画、慢眨眼 | 仅真正退出会话后显示待机 |
| 唤醒/连接 | 睁眼一次，连接期间保持清醒 | 显示“正在连接”；连接及收音未就绪不能显示“我在听” |
| 聆听 | 专注眼神、闭嘴；不随机跳表情 | 收音真正启用后显示“我在听” |
| 思考 | 疑惑/思考眉眼，嘴闭合 | 判停后即显示“正在思考”；等待超过 2 秒改为“让我想想” |
| 工具查询 | 同一思考表情，不重启动画 | 只有真实工具执行事件才显示“正在查询” |
| 说话 | 本轮选定情绪的眉眼；嘴型跟随扬声器 PCM | 按短句显示回复，不念情绪标签 |
| 播完恢复 | 保持表情并闭嘴，等待现有播放排空及回声保护完成 | 收音启用后显示“你接着说”，再开始现有等待讲话计时 |
| 失败/停止 | 立即停止嘴型和普通过渡，显示疑惑/错误状态 | 区分“没听清，请再说一次”“回复未完成，请重试”“网络断开，正在重连”；普通情绪不得遮盖错误 |

失败重试沿用有限重试约束：已明确空识别的轮次清理后只开放一次重新聆听窗口；后续仍失败则提示重新唤醒。不要仅凭阿里 Listening 状态就断言空识别。未收到最终识别结果与已识别但未生成音频分开记录，不跨供应商自动切换。

## 实现边界

### 会话状态与情绪

应用层继续拥有收音、轮次、播放和退出状态；NOCAM 显示适配器只负责绘制，不能启动录音或决定退出会话。显示侧保存当前交互阶段、目标情绪、当前资产及切换时间，不用 GIF 是否结束推导会话是否结束。

沿用现有 llm.emotion 和 turn_id；普通情绪归属当前轮次，旧轮次事件直接拒绝。串联路线保留 FaceControlParser 的流式标签过滤，托管路线只接受已实现的明确请求，普通内容默认中性。不得根据“我很生气”等孤立情绪词触发机器人生气。

复用映射：开心→silly，惊讶→surprised，疑惑→confused，关心→caring，难过→sad，害羞→shy，生气→angry。开始播放只改变阶段，不覆盖情绪。新轮次、停止、错误立即清除旧轮次情绪及待执行切换；重复请求同一资产不重启动画。

普通情绪保持至少 1500 ms；期间的新情绪只保留最新一个待执行目标，不建立无界队列。状态切换和错误不受保持时间限制。过渡采用约 200 ms 的眨眼遮挡：闭眼过程中替换眉眼资产、再睁眼；不整屏淡出到黑，也不同时解码两套 GIF。现有 GIF 自带眨眼不同时叠加第二次眨眼。

### PCM 嘴型与资源

复用 CAM 板型 OutputData 的 PCM 电平采样方式，NOCAM 编解码器只发布电平和更新时间，不调用 LVGL、不等待动画。显示定时更新上限 20 Hz，GIF 保持原 10 FPS。初始沿用既有噪声门限 180、参考幅度 5000、每 8 个样本抽样；保留板型内校准常量，真机确定最终值。

未处于说话状态或电平超过 180 ms 未更新时闭嘴；使用现有攻击/释放平滑策略避免嘴型抖动。PCM 数据不保存、不上传用于动画。输出队列排空才结束说话，不能提前关闭音频缩短动画。

既有 GIF 含嘴部，不能直接叠加第二张嘴。实现前逐资产确认嘴部区域及背景；在显示帧中还原该区域的背景，再绘制闭合、微张、张开三档嘴型，眉眼保留。每套资产保留有界的嘴部遮罩/底图，不替换整套角色、不全帧复制双缓冲。若某套素材无法可靠分离，保留静态嘴并标记该素材嘴型未通过，不能以双嘴或矩形色块放行。

### 字幕与状态文字

仅改 NOCAM 显示适配器；停止横向循环滚动。字幕最多两行，按实际字体换行。优先按句末标点分段，超长句按字体测量分页，最多暂存当前句和一个待显示页；停止、失败、新轮次清空旧字幕。

托管接口返回的是累计 spoken 文本，显示侧按新增内容更新，不能每个事件重置为句首。接口没有逐字时间戳时，仅承诺短句字幕，不承诺逐字卡拉 OK 同步。状态文字优先于装饰动作，激活二维码和错误覆盖层保持最高显示层级。

## 验证和发布

1. 主机检查：状态优先级、1500 ms 保持、最新目标覆盖、过渡期间取消、旧 turn_id、重复资产、静音/过期电平闭嘴、字幕页边界及累计文本去重。测试动态执行行为，不仅匹配源码字符串。
2. 后端回归：明确表情请求与否定/叙述对照；跨块情绪标签不得进入 TTS；失败仍记账，取消后旧任务不得继续更新屏幕。
3. 真机比较：同版连续 20 轮，含短句、长句、停顿、第二轮追问、停止、断网恢复；先通过冒烟再进入既定两组各 50 轮验收。未回复和慢样本全计入。
4. 对照记录首响、播放排空、内存最低水位、音频队列异常和动画帧耗时；主音频任务不得等待显示锁。保持既定 P50≤2 s/P90≤2.5 s 目标，不因表情放宽。没有完成资源测量不称为性能通过。
5. 发布前核对运行中的 Bootstrap 路由与构建 sdkconfig；完整备份后仅写必要分区，记录哈希。后端与固件以同一冻结提交生成最终候选，旧固件继续兼容已有消息。
6. 记录同一候选完整多轮视频与外部录音，确认没有双嘴、黑闪、尾字丢失、情绪标签播报。用户提供拍摄；自动检查不能冒充实听。
7. 固件或会话行为更新后重计长稳，保留旧版本结果但不拼接。交付报告分开列代码通过、实际部署、用户反馈、待验收四类证据。

不新增数据库表、公共接口、供应商、自然语音打断或硬件。没有再次验证第二轮前，不把本阶段整体标记完成。

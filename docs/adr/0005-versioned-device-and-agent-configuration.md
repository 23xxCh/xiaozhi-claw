# ADR 0005：设备与助手配置采用版本化回执

- 状态：接受
- 日期：2026-08-13

## 目标

客户修改设备或助手参数后，系统必须区分“已保存”“已下发”和“设备已应用”，不能把 WebSocket 发送成功当作硬件已经生效。

## 决策

- 设备首批开放扬声器音量和屏幕亮度，范围均为 `10–100`。
- 设备配置使用单调递增的 `config_version`。控制面保存期望值，实时网关通过数据库 Outbox 下发，ESP32 写入 NVS 后返回 `device_config_ack`。
- ESP32 整组校验配置；任一字段非法时整组拒绝，不进行部分应用。
- 旧版本、重复版本和离线设备均可安全处理。数据库分别保存期望版本、已应用版本和最后错误。
- 助手首批开放 LLM 温度 `0–2` 和 TTS 语速 `0.5–2.0`，沿用助手 `config_version`，从下一轮 `listen.start` 生效。
- 客户页面不暴露 Provider URL、API Key、麦克风增益、AEC 或摄像头底层参数。

## 数据流

```text
网页 PATCH 配置
    -> 控制面保存 desired_version
    -> DeviceCommand Outbox
    -> 实时网关 WSS system/apply_config
    -> ESP32 校验、应用、写 NVS
    -> device_config_ack
    -> 网关更新 applied_version
    -> 网页显示 已生效 / 等待设备 / 应用失败
```

## 失败与恢复

- 设备离线：配置保留为等待设备，不误报成功。
- 下发后无回执：保持等待状态，用户可再次保存触发新版本。
- 旧回执迟到：只结束对应命令，不覆盖更高的已应用版本。
- 设备拒绝：保存稳定错误码，网页允许重试或恢复默认值。
- TTS 实时服务降级为批量服务时，批量语音可能暂时使用默认语速，必须在用量记录中标记降级。

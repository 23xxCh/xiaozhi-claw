# ADR 0004：邮箱一次性验证码登录

- 状态：接受
- 日期：2026-08-13

## 决策

客户控制台使用邮箱一次性验证码作为主要登录方式。验证码为 6 位数字，10 分钟有效，60 秒后才可重发，最多允许 5 次错误尝试，成功后立即作废。服务端只保存带独立密钥的验证码哈希，不保存或记录明文验证码。

生产环境通过配置的 SMTP 服务发送验证码，响应中绝不包含明文验证码。开发和测试环境不假装已经发信，而是在响应和页面中明确展示仅限本机使用的测试验证码。

微信 OAuth 接口暂时保留用于已有账户兼容和未来账户合并，但客户登录页不再展示微信扫码入口。已有试点数据库在开发环境中只有一个未绑定邮箱的历史账户时，首次成功邮箱验证会把邮箱绑定到该账户，保留设备、助手、记忆和权益归属；生产环境不执行这种自动合并。

## 安全边界

- 请求验证码按邮箱和来源地址限速。
- 登录接口不暴露邮箱是否已经注册。
- 验证码单次使用，过期、超限或已使用后必须重新申请。
- 邮箱统一转成小写并去除首尾空格。
- 新邮箱只完成身份验证，仍需单独完成 18+、AI 提示、隐私政策和服务协议确认。
- SMTP 密码、验证码、会话 Cookie 和访问令牌不得进入浏览器构建物、日志或 Git。

## 后果

- `User` 增加可选邮箱和邮箱验证时间，微信标识改为可选。
- 增加短期邮箱验证码挑战表及清理策略。
- `/v1/auth/email/request-code` 负责发送验证码，`/v1/auth/email/verify-code` 负责登录。
- 正式部署前必须配置 SMTP、启用 HTTPS 和 Secure Cookie，并验证退信、垃圾邮件与发件域名策略。

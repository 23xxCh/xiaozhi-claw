# Hensun 生产级改造方案与静默审查

日期：2026-09-08；基线：699eeb5；范围：E:/HENSUN_STABILITY_WT。

## 结论

生产准备度暂评 60/100：仅适合受控内部验证，不作零售或企业 SLA 承诺。这是依据当前工程证据的排序判断，不是安全认证或完成百分比。保留 Next.js、FastAPI 控制面、独立语音网关、ESP-IDF；生产使用已有 MySQL 部署路线，不把当前 LAN SQLite 运行状态当成生产环境。

企业级目标是可控失败、可追溯变更、可恢复数据、可验证容量，而不是提前拆微服务。当前没有证据要求 Kubernetes、Kafka、插件市场或同时支持多个数据库产品。

本轮没有切换真实设备角色、播放试听、调用语音供应商、刷固件、重启服务或向服务器发布。代码审查和静默检查不替代真机听感或服务器演练。

## 执行顺序及交付

第一批，静默基础门禁：修复 lint；统一候选路由准入；保持完整回归。交付代码、失败用例、通过记录和回退说明。

第二批，静默语音可靠性：限制接收缓冲；异常事件形状、断流、超时、取消、设备不确认播放的故障注入；证明资源回收。复用当前模拟设备和双进程脚本，不驱动真实硬件。

第三批，静默业务闭环：隔离数据库与账户的网页 E2E、迁移、重复赠送/并发保存/解绑撤权、删除记忆。UI 成功提示必须对应真实写入成功。

第四批，预发布运营：准备不可变产物、目标 MySQL 恢复和多网关/容量实验、告警与应急流程。需要实际服务器的操作待执行范围明确后进行，本轮不发布。

第五批，环境允许出声后：每条路线两组各 50 次、每组至少 5 会话；实听尾字、停止、断网、表情、2 小时连续对话与8小时待机。之后才进入5台内部、20台成人至少7天试用。

每批只做验收所需的最小改动；不能因缺少硬件反馈而把未验证能力设置为生产默认。第一批的软件时间可短，但第五批不可用自动测试替代，也不承诺五天商业上线。

## 建议的运营目标（待实测校准，不是现有承诺）

- 延续已约定整机门槛：每条路线成功率≥98%，服务端确认语音结束至 speaker_pcm_started 的 P50≤2000ms、P90≤2500ms，实听延迟另测；这是发布体验门槛，不是月度 SLA。
- 月度 SLO 在容量测试后制定；分别计账户 API 和对话完整成功，说明失败分母、供应商故障、取消和过载的统计口径，不能删除慢/失败样本改善数字。
- 数据恢复初始建议目标：RPO≤15分钟、RTO≤60分钟，需要备份/日志归档和真实恢复测量支持；普通每日备份不能满足前者。若成本或部署达不到，应调整产品承诺，而不是填“通过”。
- 明确运营职责：发布批准、故障响应、凭据轮换、数据恢复和用户通知各有负责人。没有值班安排，不承诺7×24人工响应。

## 国内与海外

先完成国内成人产品。区域凭据、数据库/备份、服务端点和日志保留策略按部署隔离；国内记忆不自动搬到海外。先选市场再验证语言、网络、供应商可用性和商业使用条件，支付及法规评估作为区域上线前工作，不提前造空实现。

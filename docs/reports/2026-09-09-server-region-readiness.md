## 入口测量

| 控制 API 回环 13001 | 200 | 6.1 / 5.2 / 4.9 |

| 公网 `staging.hensun-desk.top` | 200 | 1347 / 1191 / 1419 |

本机 HTTPS 用 `--resolve` 保留 Host/SNI，连接 127.0.0.1。正常证书验证返回 curl 60（本机信任链无法验证）；仅这次不含凭据的回环诊断用 `-k` 测代理耗时。该结果不代表源站证书适合设备直连，不应把关闭验证写入产品。

证据支持优先调查公网线路、边缘入口和回源路径，尚不能单独归因 Cloudflare，也不是语音首响或设备登录故障的根因证明。公网请求握手、路由与长连接稳态延迟必须分别测量。

## 磁盘原因与处理边界

DockerRoot 已在 `/data/docker`，但 `/var/lib/containerd` 仍占根分区约 19489 MiB，其中快照约 14849 MiB、内容块约 4634 MiB。日志约 101 MiB，不是主要来源。

Docker 官方说明：containerd 存储目录独立于 Docker data-root，修改后者不会自动迁移前者：[官方说明](https://docs.docker.com/engine/storage/containerd/)。

`docker system df` 报告镜像 18.13 GB、可回收 6.725 GB；没有悬空镜像，构建缓存报告可回收 0 B。可回收不等于可安全删除：其中含历史回退镜像。

最小删除候选（尚未批准或执行）：

- 标签：`hensun-desk-backend:ac426870b044f9199e9d003e5860a29b7b68c9b9`
- ID：`sha256:b3b06a19e64cb73b5ab591d77576038d81e5e7e20d81751355e7aa7c814db922`
- 检查时容器引用数 0，独占空间约 808.5 MB；实际回收空间以操作后 df 为准。
- 删除会失去该历史镜像的直接回退能力。当前版本、`41439eea809412d43603bd62142cd06ff4825ba8` 基线和其他回退版本保留。
- 执行前重新核对标签 ID、所有运行/停止容器引用和回退依赖；任何变化停止处理。单独确认后才可按标签执行 `docker image rm`，不用 force 或全局 prune。

长期方案是维护窗口内迁移 containerd 到数据盘，但涉及该主机全部容器。需独立的备份、服务停机顺序、配置核对、回退和全服务恢复验收，当前不实施。

## 香港隔离对照执行清单

1. 候选项目名 `hensun-region-test`，候选域名 `hk-test.hensun-desk.top`。湖北系统解析器当前无法解析该名字，不等于权威 DNS 无冲突证明。创建前核对权威记录并确认准确域名；目前未创建。
2. 两端使用同一不可变镜像、角色提示词、模型、音色和测试样本。单独测试账户与数据库，不复制国内用户或记忆。第一阶段只测入口和模拟音频传输，真实供应商测量另记费用与样本。
3. 现有 Compose 依赖共享 MySQL、固定端口与网络，不能原样复制到香港。复用现有发布工具，隔离项目、数据库和回环端口，显式限制全部服务及迁移任务资源。
4. 香港保留至少 2 GiB 内存、15 GiB 磁盘；现有三个应用服务上限合计约 3.5 GiB，迁移任务和构建峰值另计。部署前复测资源，构建与运行峰值不符合预算则不部署。
5. 入口要求有效证书、WebSocket 支持和连接超时配置；分别记录设备网络至入口、入口至源站、服务至供应商。不得为跑通测试关闭设备证书验证。
6. 同一设备网络交替测两端，至少两组各 50 轮、每组至少 5 会话；保留失败/超时样本。记录首响 P50/P90、断连、完整播放、取消、两小时稳定性。维持现有验收口径：服务端确认语音结束至设备 `speaker_pcm_started`。
7. 只有同版本实测显示目标用户网络上的稳定改善，并满足成本、容量与数据边界，才提出迁移。测试结束仅停止隔离测试服务，清理数据另按明确范围处理。

## 后续检查：公网绕路与实际回源

同日补查，通过 cloudflared 日志中已加载的路由确认，该域名转发至 `http://127.0.0.1:10444`。对此实际回源入口保留 Host 测量，三次均 HTTP 200，耗时 8.90 / 5.54 / 5.50 ms。因此前面的 443 回环测试不是隧道实际回源，实际回源也很快。

湖北系统 DNS 返回 Cloudflare 地址。该服务器访问域名 `/cdn-cgi/trace` 显示 `colo=AMS`，响应 Cf-Ray 也以 AMS 结尾。cloudflared 本机指标显示四条活动连接，当前 location 为 lax08、sjc08、lax05、sjc11，连接协议日志为 QUIC。这些代码对应阿姆斯特丹入口以及洛杉矶、圣何塞隧道节点，存在跨洲路径。

在同一 HTTPS 连接上交替请求边缘 trace 和回源健康检查：

| 请求顺序 | 路径 | 耗时 ms | HTTP |
|---|---|---:|---:|
| 1 | trace，含首次建连 | 1681 | 200 |
| 2 | health | 1511 | 200 |
| 3 | trace | 221 | 200 |
| 4 | health | 842 | 200 |
| 5 | trace | 221 | 200 |
| 6 | health | 550 | 200 |

结论：该测量点的公网跨区路径是明显的延迟来源；不是单纯 DNS 或首次 TLS 握手慢。样本少，trace/health 响应处理不同，不能直接相减作为精确隧道单程延迟。也不能外推为设备网络的线路、实时 WebSocket 音频延迟或登录失败的唯一根因。

指标中的请求错误 786、总请求 44465 是整个 cloudflared 进程的累计量，包含其他域名，不能作为 Hensun 当前错误率。指标位置以值 1 为当前、0 为历史，依据 [Cloudflare 官方指标说明](https://developers.cloudflare.com/tunnel/monitoring/)。

下一步应从设备所在网络复测实际配置的服务器地址，再准备独立的区域入口对照。湖北是 NAT 服务器，不能通过简单取消 Cloudflare 代理保证公网直达；需要先核实可用的正式 HTTPS/WSS 接入方式。共享隧道承载其他服务，不通过重启或随意改协议碰运气，也不把香港部署继续接同一绕路入口当作有效对照。本轮未修改任何服务器配置。

另：经用户明确授权，最小候选 `ac426870…` 镜像已删除，完整 ID 与容器引用已核对。根盘实际释放 808661504 字节，使用率 81% 降至 78%；Hensun 三服务仍健康、ready 返回 200。其他候选未删。

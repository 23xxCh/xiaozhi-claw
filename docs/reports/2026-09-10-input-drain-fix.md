# 输入结束收尾修复（第一项）

对应全局审查的“停止消息越过剩余音频”路径。本次保留固件协议及所有供应商路线，只调整正常输入结束。

- AFE/Lite 停止 PCM 输出时与输出线程互斥，保留已处理的末帧；不足一个 Opus 帧的部分补零，最多补不足 60ms，不删除有效样本。
- AudioService 等待编码队列为空且没有在途编码，最长等待 1000ms。编码失败或队列溢出使该轮收尾失败，不能正常提交残缺输入。
- 应用发送剩余 Opus 包后才发送 listen.stop；发包失败或收尾失败进入现有取消路径。现有取消、TFT 错误提示和跨层超时的改进另行完成。

## 验证

- C++ 主机动态检查直接编译生产 FinishVoiceInput、HandleStopListeningEvent、AFE/Lite FinishVoiceProcessing 方法；硬件和编码器用测试替身，不是假装真实 ESP 调度。
- 覆盖在途编码尚未完成、包顺序、重复停止、收尾超时、溢出、网络发送失败、末帧补零和 AFE 输出与停止互斥。
- 移除在途编码判断后，动态检查按预期断言失败，证明能捕获该回归。
- 主机动态检查及相关三组固件检查合计 79 passed；新增 Python 检查通过 Ruff。
- ESP-IDF 6.0.2 NOCAM local 最终构建通过，应用 2792640 字节；SHA256 `2503d4e6338bcbb79084b4c099582638ca2c9ff00c631273a5657c1873608450`。本次未烧录。
- CI 固件作业已加入该动态检查；使用宿主 C++17 编译器。Windows 本次使用 tmp 下隔离的 Zig 工具，不增加产品运行依赖。

## 边界

本次保证已经交给 PCM 输出/编码队列的音频在正常结束时收尾；不宣称能够补回 AFE 尚未处理、硬件未采到或网络已经丢失的音频。等待编码有界，网络发送仍采用现有协议超时。

旧 VAD 应用事件的轮次隔离、统一无结果期限、取消来源记录和用户可理解的错误反馈仍未完成。本次为独立候选修复，不代表“不回复”已全面解决；最终固件构建、烧录与真机记录应分别记录，不能拿主机替身检查当作真机验收。
